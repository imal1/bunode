

## 1. 项目概述

### 1.1 产品定位

开发一款专为 macOS 设计的轻量级 Node.js / Bun 图形化进程管理工具。

面向日常使用 Node.js、Bun、npm、pnpm 等工具的开发者，统一管理本地运行的开发服务器、API 服务、Bot、MCP Server 及其他 JavaScript/TypeScript 后台进程。

产品定位类似 Quay，但更专注 Node.js / Bun 生态，强调：

- 简洁、美观、符合 macOS 设计规范。
    
- 稳定可靠，不出现 GUI 卡死、进程无法终止等问题。
    
- 快速启动、停止、重启和监控多个项目。
    
- 自动发现运行中的 Node/Bun 进程。
    
- 支持实时日志、资源监控和端口查看。
    
- 轻量、低内存占用、低 CPU 占用。
    
- 本地运行，无需浏览器、云服务或账户。
    
- 开源免费，不设置功能付费墙。
    

### 1.2 目标平台

|项目|要求|
|---|---|
|操作系统|macOS 13+|
|CPU 架构|Apple Silicon 优先，兼容 Intel|
|运行时|Node.js、Bun|
|包管理器|npm、pnpm、yarn、Bun|
|产品形态|macOS 桌面 App + 菜单栏|
|网络依赖|核心功能完全离线|
|浏览器|不依赖浏览器|
|数据存储|本地持久化|
|开源协议|MIT|

## 2. 技术架构

### 2.1 建议技术栈

|层级|技术|
|---|---|
|桌面框架|Tauri 2|
|前端框架|React + TypeScript|
|UI 组件|shadcn/ui|
|样式|Tailwind CSS|
|图标|Lucide|
|状态管理|Zustand|
|前端构建|Vite|
|系统进程管理|Rust|
|异步运行时|Tokio|
|系统信息|sysinfo 或 macOS 原生 API|
|数据存储|SQLite 或 JSON|
|包管理器|Bun|

优先保证稳定性和较低资源占用，不为了技术栈统一而使用 Electron。

### 2.2 架构设计

采用 UI 与进程管理核心分离的架构。

```
macOS Application
│
├── Tauri / React UI
│   ├── Dashboard
│   ├── Project Manager
│   ├── Process Explorer
│   ├── Log Viewer
│   └── Settings
│
├── Rust Backend
│   ├── Process Supervisor
│   ├── Process Discovery
│   ├── Port Scanner
│   ├── Resource Monitor
│   ├── Log Collector
│   └── Project Repository
│
└── Optional Background Supervisor
    ├── Process Lifecycle
    ├── Auto Restart
    └── State Synchronization
```

关键要求：

1. 所有进程扫描、端口检测、资源采样和日志读取都必须异步执行。
    
2. UI 线程不允许直接执行阻塞式系统命令。
    
3. 高频日志不能导致 React 页面持续全量重渲染。
    
4. 进程监控采用增量更新和合理轮询间隔。
    
5. 每个进程具有独立的状态机和生命周期管理。
    
6. 系统进程发现与本应用创建的托管进程必须分离。
    
7. 不得因为单个进程异常而影响整个应用。
    
8. 后端异常不能使 UI 永久停留在 Loading 状态。

## 3. 核心功能

### 3.1 项目管理（P0）

支持以项目为单位管理 Node/Bun 服务。

**添加项目**

提供三种方式：

- 选择本地项目文件夹。
    
- 手动配置启动命令和工作目录。
    
- 从已发现的运行中进程创建项目配置（能够可靠恢复启动参数时才允许）。
    

**自动识别**

扫描项目目录中的：

- `package.json`
    
- `bun.lock` / `bun.lockb`
    
- `package-lock.json`
    
- `pnpm-lock.yaml`
    
- `yarn.lock`
    
- `.nvmrc`
    
- `.node-version`
    
- `.env` 等环境配置文件
    

根据项目配置识别可用脚本。

例如：

```
{
  "scripts": {
    "dev": "vite",
    "start": "node server.js",
    "worker": "bun worker.ts"
  }
}
```

在 GUI 中直接选择运行脚本。

**项目配置字段**

|字段|说明|
|---|---|
|Name|项目名称|
|Directory|工作目录|
|Runtime|Auto / Node / Bun|
|Package Manager|Auto / npm / pnpm / yarn / Bun|
|Command|启动命令|
|Arguments|启动参数|
|Environment|环境变量|
|Auto Start|自动启动|
|Auto Restart|异常自动重启|
|Group|项目分组|

支持编辑、复制、删除项目配置，以及项目搜索、排序和分组。

删除项目配置不能删除项目源代码。

### 3.2 进程生命周期管理（P0）

每个托管项目提供以下操作：

- Start：启动。
    
- Stop：正常停止。
    
- Restart：重启。
    
- Force Kill：强制结束。
    
- Open Folder：打开目录。
    
- Open in Editor：使用编辑器打开项目。
    
- Open URL：打开服务监听地址。
    

**进程状态**

```
Stopped
   │
   ▼
Starting
   │
   ├──> Running
   │       │
   │       ├──> Stopping ──> Stopped
   │       │
   │       └──> Crashed
   │                  │
   │                  └──> Restarting
   │
   └──> Failed
```

要求：

1. 一个项目可以定义多个运行配置。
    
2. 允许多个不同项目同时运行。
    
3. 防止重复点击导致重复启动。
    
4. 支持启动、停止、重启过程中的状态反馈。
    
5. 子进程退出后及时更新状态。
    
6. 进程退出后正确释放资源。
    
7. 支持发送 SIGTERM，超时后经用户配置或确认升级为 SIGKILL。
    
8. 必须正确管理进程组，避免 npm、pnpm、Bun 等启动器留下孤儿进程。
    
9. 防止误杀 PID 被系统复用后的无关进程。
    
10. 支持崩溃自动重启，并限制重试频率和连续重启次数。
    

**特别要求**

关闭主窗口不应结束托管进程。用户显式退出应用时，需提供清晰的进程保留策略。

如需在 GUI 完全退出后继续运行托管服务，应通过独立后台 Supervisor 实现，不允许简单地依赖 WebView 生命周期。

不得为了保留后台进程而让整个图形窗口始终运行。

### 3.3 自动进程发现（P0）

自动扫描当前用户运行的 Node.js / Bun 相关进程，包括：

- `node`
    
- `bun`
    
- `npm`
    
- `pnpm`
    
- `yarn`
    
- 通过这些工具启动的 Vite、Next.js、Nuxt、Astro 等开发服务器。
    

展示：

|字段|内容|
|---|---|
|Process|进程名称|
|PID|进程 ID|
|Runtime|Node / Bun|
|Project|关联项目|
|Command|启动命令|
|Directory|工作目录|
|Port|监听端口|
|CPU|CPU 使用率|
|Memory|内存使用量|
|Uptime|运行时间|

进程发现需要考虑父子进程关系，避免将 `npm run dev` 和它启动的 Vite 错误地显示为两个独立服务。

**托管进程和外部进程分开处理：**

- Managed：由本应用启动，支持完整生命周期操作。
    
- Discovered：由终端、IDE、Codex 等工具启动，默认提供查看及安全终止功能。
    

外部进程只有在能够可靠恢复工作目录、命令、参数及环境的情况下才能提供重启操作。

不能将 Kill + 猜测命令重新启动伪装成可靠的 Restart。

### 3.4 实时日志（P0）

支持查看托管进程的标准输出和标准错误。

功能：

- 实时滚动显示日志。
    
- stdout/stderr 区分。
    
- 时间戳。
    
- 关键词搜索。
    
- 日志级别过滤。
    
- 自动滚动开关。
    
- 清空当前显示。
    
- 复制日志。
    
- 导出日志文件。
    
- 支持 ANSI 颜色。
    

**性能要求**

- 日志采用有界缓冲区。
    
- 大量日志持续输出不能导致 GUI 卡死。
    
- 使用虚拟列表渲染。
    
- 批量更新 UI，禁止每条日志引发一次完整组件树更新。
    
- 日志必须支持背压或丢弃策略，并提示丢弃情况。
    
- 磁盘日志文件需要限制大小并支持滚动归档。
    
- 外部发现的进程不保证可以追溯历史 stdout/stderr，不得虚构日志内容。
    

### 3.5 端口管理（P0）

- 自动检测 Node/Bun 服务监听的 TCP 端口。
    
- 支持一个服务同时监听多个端口。
    
- 展示端口状态。
    
- 点击端口打开对应 localhost 地址。
    
- 启动前检查预期端口冲突。
    
- 端口冲突时显示占用进程信息。
    
- 支持用户手动配置预期端口。
    

不得自动结束不属于本应用的端口占用进程。

### 3.6 资源监控（P1）

展示：

- 实时 CPU 使用率。
    
- 内存占用。
    
- 运行时长。
    
- 进程数量。
    
- 监听端口。
    
- 退出码与最近异常。
    

允许查看单个项目的资源使用变化。

默认采用低频采样，在窗口隐藏时主动降低采样频率。

避免为了监控性能而引入明显的系统资源开销。

### 3.7 菜单栏（P0）

提供 macOS Menu Bar 常驻入口。

菜单栏应支持：

- 查看当前运行服务数量。
    
- 查看全部项目。
    
- 快速启动/停止项目。
    
- 重启项目。
    
- 查看异常状态。
    
- 打开主窗口。
    
- 退出应用。
    

菜单栏与主窗口必须共用同一状态来源，避免状态不同步。

支持：

- 仅菜单栏模式。
    
- 菜单栏 + 主窗口模式。
    
- 启动时最小化到菜单栏。
    

### 3.8 自动启动与恢复（P1）

支持：

- macOS 登录时启动 GUI。
    
- 登录时自动启动指定项目。
    
- GUI 意外退出后的状态恢复。
    
- 后台 Supervisor 异常重启后的进程状态对账。
    
- 项目异常退出时按策略重启。
    

区分：

- 用户主动停止。
    
- 程序异常退出。
    
- 操作系统重启。
    
- GUI 关闭。
    
- 后台服务退出。
    

用户主动停止的项目不得被自动重启策略立即重新拉起。

界面采用现代 macOS 开发工具的设计风格。

参考 Raycast、Linear 等产品的视觉语言，但不直接复制。

设计要求：

- 简洁、现代、高信息密度。
    
- 不使用传统系统进程管理器式的拥挤表格作为唯一主界面。
    
- 支持深色与浅色主题。
    
- 优先使用系统字体。
    
- 合理使用颜色表示状态。
    
- 少弹窗、少层级、少复杂配置。
    
- 支持键盘快捷键。
    
- 所有常用操作尽量在两次点击内完成。
    
- 动画轻量，不影响操作响应。

## 5. 稳定性与性能要求

这是项目的最高优先级。

### 5.1 稳定性

必须重点防范以下问题：

1. 进程持续输出日志导致主窗口冻结。
    
2. 快速连续点击启停导致状态竞争。
    
3. 进程启动失败后 UI 一直显示 Starting。
    
4. 进程已退出，但 UI 仍显示 Running。
    
5. 停止父进程后遗留 Node/Bun 子进程。
    
6. 外部进程退出后 PID 复用导致监控对象错乱。
    
7. 资源监控轮询导致 CPU 占用过高。
    
8. 端口扫描阻塞 UI。
    
9. 项目数量增加导致应用响应明显变慢。
    
10. GUI 崩溃造成托管进程状态丢失。
    

### 5.2 性能目标

以下为开发验收目标，非已验证性能数据。

|指标|目标|
|---|---|
|冷启动|小于 2 秒|
|空闲 CPU|尽量低于 1%|
|空闲内存|优先控制在 100 MB 内|
|常规操作响应|100 ms 内出现反馈|
|进程状态更新|通常 1 秒内|
|同时管理项目|至少 30 个|
|高负载日志|不冻结 GUI|
|菜单栏唤出|流畅、无明显卡顿|

### 5.3 异常恢复

- 后台操作有明确超时。
    
- UI 与 Supervisor 断开时显示连接状态。
    
- 支持重新同步当前进程状态。
    
- 对意外退出提供诊断日志。
    
- 不使用无限制的自动重启循环。
    
- 应用更新或 GUI 重启不应破坏托管配置。

## 6. 安全要求

- 默认所有操作只在本机执行。
    
- 不开放远程 HTTP 管理接口。
    
- 不上传项目目录、日志或环境变量。
    
- 环境变量中的敏感值默认隐藏。
    
- 不使用 `sudo` 执行项目命令。
    
- 不允许普通启动配置隐式获得管理员权限。
    
- 优先使用可执行文件 + 参数数组启动，避免 Shell 注入。
    
- 需要 Shell 特性的命令必须显式配置 Shell 模式。
    
- 终止进程前验证目标 PID、启动时间及所属关系。
    
- 禁止无确认地批量结束外部进程。

## 8. 测试与验收

### 8.1 功能测试

必须覆盖：

1. 启动普通 Node.js HTTP 服务。
    
2. 启动 Bun HTTP 服务。
    
3. 通过 npm、pnpm 和 Bun 启动 Vite。
    
4. 同时启动 10 个不同服务。
    
5. 连续快速启动和停止同一服务。
    
6. 服务启动后立即退出。
    
7. 服务运行过程中崩溃。
    
8. 服务持续产生大量日志。
    
9. 服务生成多级子进程。
    
10. 服务占用多个端口。
    
11. 两个服务争用同一端口。
    
12. 删除正在运行项目的配置。
    
13. GUI 关闭、重新打开及意外退出。
    
14. macOS 睡眠、唤醒及用户注销。
    
15. Node/Bun 可执行文件不存在或版本切换。
    
16. 项目工作目录被移动或删除。
    
17. 外部终端启动的 Node/Bun 进程被自动发现。
    
18. 高频启动、停止操作下的并发安全性。
    

### 8.2 稳定性测试

- 连续运行至少 24 小时。
    
- 持续高频日志输出 30 分钟。
    
- 反复启停同一项目至少 100 次。
    
- 同时运行 30 个低负载测试服务。
    
- 多次关闭和恢复主窗口。
    
- 模拟 Supervisor 异常退出。
    
- 检查内存泄漏、僵尸进程和遗留进程。
    
- 检查所有托管进程的最终状态与 UI 是否一致。
    

### 8.3 验收标准

MVP 必须满足：

- 不依赖终端完成基本项目管理。
    
- Node 和 Bun 都可以稳定启动、停止、重启。
    
- 支持运行时日志查看。
    
- 能自动发现外部 Node/Bun 进程。
    
- 进程异常退出能够正确反映到 UI。
    
- 不出现不可恢复的 Starting / Stopping 状态。
    
- 大量日志不能卡死主界面。
    
- 主窗口关闭后菜单栏仍可管理服务。
    
- 不误杀其他应用或无关进程。

## 10. 开发原则

1. **稳定性优先于功能数量。**
    
2. **专注 Node.js / Bun，不演变为通用系统管理器。**
    
3. **优先复用成熟的 Rust / macOS 系统能力。**
    
4. **所有影响进程生命周期的操作必须有可测试的状态转移。**
    
5. **UI 不承担进程生命周期的真实状态管理。**
    
6. **不允许阻塞 UI 主线程。**
    
7. **不依赖高频全量轮询实现所有状态同步。**
    
8. **界面现代、紧凑，避免功能堆砌。**
    
9. **保持可维护的模块化结构，避免过度设计。**
    
10. **优先实现完整、稳定的 MVP，再逐步扩展。**
